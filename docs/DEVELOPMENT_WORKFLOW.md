# Sol / Luna 開発運用

この文書は、`picocalc_emu`でSol（監督者）とLuna（実装者・定型作業担当）を分担するための運用ルールを定義する。プロジェクト内の役割名は`Luna`、利用するdelegated model名は`gpt-5.6-luna`とする。

## 1. 役割と責任

### Sol（監督者）

Solはプロジェクト全体の判断と完遂責任を持つ。担当範囲は次のとおり。

- 要件と既存資料を理解し、計画・設計・実装方針を決める。
- 受入条件を定義し、作業を具体的な境界のあるタスクへ分割する。
- Lunaへ作業範囲、変更対象、禁止事項、検証方法を指示する。
- Lunaの変更差分を読み、設計・仕様・既存資産との整合をレビューする。
- 必要な独立検証を実行し、受入条件を満たした場合だけ成果を統合する。
- commit、push、リリース、CI結果・実機結果の最終判定を行う。
- 人間へ実機操作を依頼するかを判断し、ユーザーへ最終報告する。
- 進捗、失敗、未解決事項を含め、プロジェクトを完遂へ導く責任を負う。

### Luna（実装者・定型作業担当）

LunaはSolが明示的に限定した範囲だけを担当する。

- 指示されたソース・文書の実装、定型編集、調査、ビルド、テストを行う。
- 指示された変更ファイルだけを変更し、範囲外の改善や設計変更を追加しない。
- 変更ファイル、実行したコマンド、検証結果、未解決事項をSolへ提出する。
- 不明な仕様、境界を越える問題、受入判断が必要な事項は推測で決めず、Solへ報告する。

Lunaは、Solの明示指示なしにcommit、push、リリース、実機試験の依頼、作業範囲の拡大を行わない。Lunaの自己検証は報告資料であり、Solの独立検証や最終受入を置き換えない。

## 2. 作業の受け渡し

通常の1タスクは次の順序で進める。

1. Solが目的、受入条件、変更可能ファイル、禁止事項、実行すべき検証を指定する。
2. Lunaが指定範囲だけを実装または調査し、差分と検証結果を提出する。
3. Solが差分を読み、必要な資料・既存実装との整合を確認する。
4. Solが独立検証を行い、受入条件を満たすか判定する。
5. 合格した場合だけSolが統合し、必要に応じてcommit・pushする。不合格または不明確な場合は、Solが追加指示を出す。

SolはLunaの成果を盲目的に採用しない。Lunaが「pass」と報告した場合でも、受入条件、生成物の同一性、ログ、テスト結果をSolが確認してから採用する。

## 3. 実機検証と人間への依頼

機械で代行できるビルド、ログ解析、ハッシュ計算、ホストテストはSolまたはLunaが行う。人間へ依頼するのは、画面の見読性、物理キー操作、聴感など機械で代行できない最小限の操作だけとする。

Solは実機依頼を一度に一セッションだけ提示し、対象UF2、固定ファイル名、必要な操作、ログ保存方法、終了条件を明確にする。LunaはSolの指示なしに人間へ実機試験を依頼しない。

## 4. 分担の境界

緊急で密結合な判断、設計変更、受入判断、または次工程を即時にblockする作業はSolが直接行う。具体的で境界の明確な実装、文書の定型更新、機械的な検査・ビルド・テストはLunaへ渡す。SolとLunaは同じ範囲を重複して編集せず、作業開始時に変更対象を明示する。

## 5. 完了報告の形式

Lunaの報告には最低限、次を含める。

- 変更したファイル一覧
- 実装・調査した内容
- 実行したコマンド
- テスト、ビルド、`git diff --check`などの結果
- 未解決事項、仮定、Solの判断が必要な事項

完遂、受入、リリース、実機合格の宣言はSolが行う。Lunaはそれらを先取りして宣言しない。
