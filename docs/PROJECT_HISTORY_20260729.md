# picocalc_emu 開発・実機検証総合履歴

作成日: 2026-07-29  
対象リポジトリ: `picocalc_emu`  
対象機器: PicoCalc / RP2040 / uf2loader

## 1. 開発目的

PicoCalc向けプログラムをAIに開発させる際、LCD、キーボード、SDカードの初期化を毎回作り直して実機で確認する負担を減らすことを目的とする。
実機で動作確認済みのプロジェクトを根拠にCanonical BSP、テンプレート、検証器、実機証拠台帳を整備し、将来はPC上でLCD・I2C・SDの動作を再現する。

## 2. 参照した実働プロジェクト

以下の既存ディレクトリを調査対象とした。

`PicoCalc`、`Picocalc_BVWCVolleyball`、`Picocalc_Clock`、`Picocalc_ClockCalc`、`Picocalc_InfoNES`、`Picocalc_NESco`、`Picocalc_scicalc`、`pico_rescue`、`pico_skyace`、`picocalc-life`、`Picocalc_ment`。

LCD初期化、リセット待機、RGB転送、RAMRD、キーボードI2C、SD初期化を比較した。

## 3. 開発段階

### 3.1 初期設計・MVP

当初はRP2040エミュレーションを含む`picocalc_emu`を構想したが、実装可能性を優先し、最初の段階を次の構成へ限定した。

- 実機動作済みコードを固定したCanonical BSP
- AIが変更する`app/`と変更を避けるBSPの分離
- プロジェクト生成器
- board profileと生成ヘッダー
- source fingerprintとLCDトランザクションのホスト検査
- 実機検証ログとSHA-256の台帳

完全なPCエミュレーター、UF2のPC実行、PNG画面取得、キーシナリオ再生は未実装である。

### 3.2 ビルド識別性

ビルド時刻、BSP版、App版、Gitコミット、UF2 SHA-256を記録する仕組みを追加した。同一版の再ビルドは警告し、意図的な再ビルドは継続できる設計とした。

重要な訂正として、当初はCanonical BSPのLCD初期化が実働プロジェクトと同一と判断していた。しかし後に`uf2loader/common/lcdspi/lcdspi.c`と直接比較し、初期化コマンド列、`COLMOD`、RGB転送長が一致していないことが判明した。

ただし、ユーザーの指示によりその比較反映版を実機検証へ進めず、現在は`9962f7b`の初期ランタイム基準へ戻している。

## 7. 現在のGit状態

運用復帰時点の実行ソースはコミット`9962f7b`（`095e768`相当）だった。その後、
版番号・コミット対応が不確かな過去UF2を再利用せず、BSP 0.2.0としてLCD実装を
再構成した。0.2.0は`uf2loader`のhardware SPI1/RGB888契約を採用し、host検証、
RP2040 UF2ビルド、実機起動スモークを通過した。

0.2.0実機ログは`pico20260729_215722.log`で、起動時にBSP/App版、ビルド時刻、LCD
transport、SD smoke、keyboard待機を記録した。生成プロジェクトでの試験だったため
当時のGit表示は`untracked`だった。この問題を修正し、以後の`tools/picocalc.py build`
では元リポジトリのGitコミットを生成プロジェクトへ渡す。

0.2.0の実機試験ではバックライトの固定輝度220が明るすぎたため、作業ツリーでは
BSP 0.2.1としてバックライト輝度を書き込まず既定状態を尊重する変更を行った。

この文書の目的は、次回以降に「どのソースをチェックアウトして、どのコマンドでビルドしたか」を追跡できるようにすることである。実機ログを取得する際は、必ず起動直後に次を出力する。

```text
[PICOCALC][BOOT] bsp=<version> git=<commit> build=<timestamp>
```

これがないログから、実機で動いた版を特定のコミットへ結び付けてはならない。
