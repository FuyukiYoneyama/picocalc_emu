# VRP-3 GUI / PicoCalc skin / LCD / keyboard / UART / reset-reload

Status: **implemented locally; VRP-3 presentation gate is complete**
Date: 2026-08-29
Scope: `picocalc_emu` thin frontend only.  The authoritative emulator remains
the byte-identical `picocalc-run` named by an admitted descriptor.

## What was added

`python3 tools/picocalc.py preview-gui` now consumes a schema-1 admitted launch
descriptor, revalidates it through the existing VRP-2 admission function, and
starts the exact runner as a child process.  The frontend does not link or
reimplement the emulator core.  PCRP stdout is parsed with the frozen schema;
malformed, truncated, unknown, out-of-order, or direction-invalid messages
make the UI sticky `UX INVALID` and are never reinterpreted.

The default presentation asset is
[`assets/preview/picocalc-device-skin.png`](../../assets/preview/README.md).
It is a metadata-stripped, owner-supplied photograph (607x1026, SHA-256
`382c5d0a33225e3771c40ab0c3b0a421a87b82bc6104a1cb2bd22d8711d467da`).  The
320x320 RGB565 frame is nearest-neighbour converted only for display and
placed in the calibrated opening `(38,69,520,475)`.  The skin and screenshot
composition cannot change cycles, UART bytes, device events, or any validation
digest.  `--skin none` selects a plain integer-scaled LCD.

## Usage

First create an admitted descriptor with an authoritative firmware PASS and
the same backend/runner bytes:

```sh
python3 tools/picocalc.py preview \
  --firmware /absolute/path/to/app.bin \
  --receipt /absolute/path/to/validation-receipt.json \
  --backend-dir /absolute/path/to/picoem-picocalc \
  --descriptor-out /absolute/path/to/admitted-descriptor.json
```

Then launch the GUI locally (this does **not** invoke GitHub Actions):

```sh
python3 tools/picocalc.py preview-gui \
  --descriptor /absolute/path/to/admitted-descriptor.json \
  --backend-dir /absolute/path/to/picoem-picocalc
```

The command opens two windows automatically:

1. PicoCalc body + LCD preview (or the bare LCD with `--skin none`)
2. A separate **PicoCalc UART0** console

The UART console is the emulated UART0 wire, not process stdin/stdout.  TX
bytes are displayed with virtual cycle and hex value.  The input control sends
UTF-8 text by default; `raw hex` sends byte pairs such as `00 ff 41`.  UART RX
accepted/overrun counters remain those reported by the backend.

## Controls

| Input | Meaning |
|---|---|
| printable key, Enter, Space, Tab, Backspace | PicoCalc keyboard `down` / periodic `held` / `up` |
| F5 | preview operator reset; sticky UX-invalid state is retained |
| Ctrl+R | stop, rerun descriptor admission, and reload only after successful revalidation |
| F12 | save a presentation screenshot under `--screenshot-dir` (default `./preview-screenshots`) |
| Esc | quit the preview (reserved; it is not sent as a guest Escape key) |

Tk/OS auto-repeat `KeyPress` events are suppressed while a key is held.  The
frontend emits a distinct `held` event on its deterministic 120 ms UI timer;
it never turns a repeat into duplicate `down` events.  Closing the UART window
only withdraws that window and records `console closed`; it does not detach or
silence the emulated UART.  While focus is in the UART entry/text window,
printable keys remain available to that editor instead of being captured as
guest keyboard events; F5/Ctrl+R/F12/Esc remain global operator shortcuts.

The status line shows the admitted validation receipt identity, target/revision,
backend/BIN pins, explicit `hardware not_claimed` banner, virtual cycle,
measured pacer ratio, timing lag/behind count, coverage, audio state, UART TX/RX
accepted/overrun/disabled/error counters, presentation-only frame drops, skin
availability, and sticky UX-invalid reason.
`audio=not_streamed` is explicit:
VRP-3 does not claim host PCM playback (that is VRP-4).  A presentation frame
drop is counted after the backend has emitted the frame; only that already-
produced display update may be coalesced.  It cannot skip a backend device
event, status, UART message, error, cycle, or authoritative observation state.

## Reload and failure semantics

- F5 releases any host-held keys, sends the schema-1 `reset` command, and keeps
  the frontend's sticky error banner.  The backend resets machine state while
  retaining its attached media according to the existing preview contract.
- Ctrl+R reopens and verifies the descriptor, target registry, validation
  record, BIN, backend HEAD/clean state, runner SHA, bootrom, and launch
  contract.  A valid reload clears only the local sticky UX state and starts a
  fresh child.  A changed/missing artifact stops the old child and leaves the
  window showing `VALIDATION LOST — RELOAD REFUSED`; no mutable fallback argv is
  constructed.
- Backend `error`, `coverage=stopped`, unsupported-MMIO attribution, truncated
  protocol data, and reader/transport failures are sticky `UX INVALID`.  The
  GUI exits with code 2 when such a state was observed.  This is a frontend
  diagnostic and does not rewrite a schema-8 validation verdict.

## Local verification

Headless contract tests (no display required):

```sh
python3 -m unittest -q tests.test_preview_gui
python3 -m unittest -q tests.test_tools
```

The tests cover frozen PCRP input fixtures, direction/payload guards, RGB565
conversion, key `down`/`held`/`up`, OS-repeat suppression, LCD-size rejection,
admission identity/status presentation, UART-entry focus, and reset/reload
sticky-state semantics.  On WSLg, a
short real-run smoke can be performed without leaving the GUI open:

```sh
python3 tools/picocalc.py preview-gui \
  --descriptor /absolute/path/to/admitted-descriptor.json \
  --backend-dir /absolute/path/to/picoem-picocalc \
  --smoke-seconds 2
```

The local smoke used the registered `picoedit-r1-vrp2f` descriptor and verified
that the body-skin window, the automatically-created UART0 window, initial
RGB565 frame, and clean child shutdown all open under WSLg.  A separate local
script also exercised key down/held/up, UART RX, reset, and observed the
explicit backend response.  No hardware write, push, tag, or CI run is part
of this record.

VRP-3 does not promote `realtime-1x-qualified`, does not add host audio
playback, and does not create a hardware verdict.  VRP-4/VRP-5 remain the
separate audio and qualification gates.
